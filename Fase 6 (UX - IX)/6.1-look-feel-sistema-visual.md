## 1. CONTEXTO DE DISEÑO Y POSICIONAMIENTO VISUAL

Democra ONG Platform es un sistema SaaS multi-tenant para la gestión integral de organizaciones
sin fines de lucro en Perú. El diseño debe equilibrar tres tensiones fundamentales:

| Tensión | Polo A | Polo B | Decisión |
|---------|--------|--------|----------|
| Complejidad vs. Accesibilidad | Sistema enterprise complejo | Usuario con nivel digital básico | Progresividad: simple a la vista, potente en profundidad |
| Densidad vs. Claridad | Mucha información operativa | Interfaces limpias y legibles | Densidad controlada por módulo (tabla densa solo cuando el contexto lo requiere) |
| Institucional vs. Humano | Seriedad y confianza | Calor, comunidad, impacto social | Paleta que combina índigo institucional con tonos tierra como acento |
| Desktop vs. Mobile | Administrativos en escritorio | Voluntarios y coordinadores en campo | Mobile-first para vistas de campo, layout denso para administración |

### 1.1 Benchmarking de Referencia

Los siguientes sistemas fueron analizados para extraer patrones aplicables al contexto de Democra ONG:

**Linear** — Se toma su sistema de densidad de listas, feedback inmediato y sidebar minimalista
con agrupamiento semántico. Se evita el enfoque oscuro y técnico que asume usuarios desarrolladores.

**Airtable** — Se toman sus múltiples vistas (tabla, kanban, calendario, galería) como modelo
de flexibilidad para módulos como Proyectos y Actividades. Se evita la complejidad de configuración
visible al primer acceso.

**Monday.com** — Se toman sus pills de estado coloridos, barras de progreso y timelines de proyecto.
Se evita el exceso de colores y la distracción visual en interfaces operativas densas.

**Rippling** — Se toma la navegación modular por dominio, dashboards segmentados por rol y el
onboarding progresivo. Se evita la densidad excesiva en vistas principales.

**Salesforce Nonprofit Cloud** — Se toma la contextualización para el tercer sector, la gestión
de beneficiarios y los flujos de admisión. Se evita el peso visual enterprise y la curva de
aprendizaje elevada innecesariamente.

**Notion** — Se toma el espaciado generoso, la jerarquía tipográfica clara y la sensación de
ligereza. Se evita la ambigüedad estructural que no es apropiada para un sistema operativo con
flujos definidos.

### 2.3 Modo Claro/Oscuro

El sistema implementa **modo claro por defecto** con un modo oscuro opcional activable por
el usuario (respeta `prefers-color-scheme`). El sidebar usa siempre dark mode
(`--gray-900` como fondo) para crear una separación visual clara entre navegación y contenido.

## 3. TIPOGRAFÍA

### 3.1 Selección de Fuentes

```
Fuente principal: "Inter" — para toda la interfaz de aplicación
Fuente de datos:  "JetBrains Mono" — para valores numéricos, códigos, IDs técnicos
Fuente de marca:  "DM Sans" — para títulos y encabezados de módulo (opcional, peso 600-800)

Fuentes de fallback:
  -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif
```

**Justificación:**
- **Inter** fue diseñada específicamente para interfaces digitales. Excelente legibilidad en
  pantallas de baja resolución (común en equipos de ONGs en Perú). Altamente legible en tamaños
  pequeños, ideal para densidad de información.
- **JetBrains Mono** mejora la lectura de datos numéricos (soles, fechas, horas, IDs) al
  alinear caracteres de igual ancho, facilitando comparación en tablas.

### 6.2 Patrones de Feedback

**Toast Notifications** (esquina inferior derecha, auto-dismiss 4s):
```

⚠️ Advertencia: bg --warning-500, ícono alerta, título + acción
❌ Error:     bg --error-500, ícono X, título + detalle, sin auto-dismiss
ℹ️ Info:      bg --info-500, ícono i, solo texto informativo
```

**Loading States:**
- Skeleton screens para tablas y listas (no spinners): rectangles grises animados
- Shimmer animation (gradiente que se desplaza de izquierda a derecha)
- Botones: muestra spinner interno + deshabilita al hacer submit
- Página completa: skeleton del layout completo, no pantalla en blanco

**Estados Vacíos:**
```
Estructura obligatoria:
  [Ilustración SVG contextual al módulo — 120px]
  [Título: "No hay {entidad} aún"]
  [Subtítulo descriptivo del siguiente paso]
  [Botón CTA: "Agregar primer {entidad}"]
```

**Confirmaciones de Acciones Destructivas:**
```
Modal de confirmación:
  Título:    "¿Eliminar {nombre}?"
  Texto:     Consecuencias claras (ej: "Esta acción no se puede deshacer.")
  Botones:   [Cancelar (ghost)] [Eliminar (danger)]
  Input:     Para acciones muy críticas, pedir escribir el nombre del elemento
```

**Indicadores de Progreso:**
- Barra de progreso lineal (slim, 4px) en parte superior de página durante navegaciones
- Progress bar en wizards: indicador de paso X de Y
- Progress bar en actividades/proyectos: porcentaje de avance
